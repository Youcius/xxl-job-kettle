# xxl-job-kettle 测试用例文档

## 1. 测试范围与目标

### 1.1 测试范围

本次测试范围覆盖自定义 Vue 管理前端及其关键后端业务流，重点包括：

- 登录页：`web/src/views/login/LoginView.vue`
- 全局布局与公共操作：`web/src/components/Layout.vue`
- 仪表盘：`web/src/views/dashboard/DashboardView.vue`
- 任务管理：`web/src/views/job/JobInfoList.vue`
- 调度日志列表：`web/src/views/joblog/JobLogList.vue`
- 日志详情：`web/src/views/joblog/JobLogDetail.vue`
- 执行器管理：`web/src/views/group/JobGroupList.vue`
- 用户管理：`web/src/views/user/UserList.vue`
- Kettle 分组：`web/src/views/kettle/GroupList.vue`
- Kettle 文件管理：`web/src/views/kettle/FileList.vue`

后端重点覆盖：

- 登录与会话：`LoginService.java`
- 任务增删改查、启动、停止、手动触发：`XxlJobServiceImpl.java`
- 调度日志查询、终止、详情查看
- 执行器注册与回调：`AdminBizImpl.java`
- Kettle 分组/文件/一键建任务：`KettleGroupServiceImpl.java`、`KettleFileServiceImpl.java`
- 权限校验、运行时约束、输入合法性校验

### 1.2 测试目标

- 确认每个页面的实际控件均可正常使用，且交互闭环完整。
- 确认关键业务流从前端到后端入参、返回、页面反馈一致。
- 覆盖最近修复与定制行为，避免回归。
- 产出可直接执行的手工测试清单，并便于后续自动化拆分。

## 2. 测试环境与账号

### 2.1 建议测试环境

- 前端：本地或测试环境部署的 Vue 管理端
- 后端：admin 服务与 executor 服务均已启动
- 数据库：独立测试库，不与生产混用
- Kettle 路径：使用测试专用目录，不引用生产任务目录
- 浏览器：Chrome 最新稳定版，另补测 Edge

### 2.2 建议账号

| 账号类型 | 用途 | 说明 |
| --- | --- | --- |
| 超级管理员 | 全量功能验证 | 可访问用户管理、执行器管理、Kettle 管理 |
| 普通用户A | 权限隔离验证 | 仅授予部分执行器组权限 |
| 普通用户B | 无权限/最小权限验证 | 用于验证受限跳转、接口拒绝 |

### 2.3 建议准备数据

- 至少 2 个执行器组，其中 1 个为内置执行器组 `xxl-job-executor-kettle`
- 至少 3 条任务：运行中、已停止、Kettle 生成任务各 1 条
- 至少 5 条日志：成功、失败、运行中、可终止日志均存在
- 至少 2 个 Kettle 分组
- 至少 4 个 Kettle 文件：`.ktr`、`.kjb`、重复文件名升级版本样例、已关联任务样例

## 3. 测试数据约束（避免碰生产 Kettle 文件）

- 所有上传的 `.ktr` / `.kjb` 文件必须使用测试样例文件，不得引用生产转换或生产作业。
- Kettle 文件存储目录、日志目录、执行目录必须指向测试路径。
- 禁止在测试环境中配置真实生产数据库、消息队列、文件目录、外部 API。
- 用于一键创建任务的文件内容应为无副作用脚本，推荐仅写日志、读测试表、写测试表。
- 文件名中可额外准备以下边界样例：
  - 正常文件名：`demo_order_sync.ktr`
  - 正常作业名：`demo_full_load.kjb`
  - 重复文件名：重复上传以验证版本递增
  - 非法文件：`.txt`、`.zip`、带双点路径特征的文件名
- 若验证删除文件/分组，请先确认无生产任务关联、无真实运行链路依赖。

## 4. 测试优先级说明

| 优先级 | 含义 | 处理原则 |
| --- | --- | --- |
| P0 | 核心路径/高风险回归 | 每次提测必测，阻塞上线 |
| P1 | 主要功能完整性 | 当日回归必测 |
| P2 | 体验/边界/异常提示 | 版本回归建议覆盖 |

本项目优先级建议：

- P0：登录、任务新增/编辑/启动/停止/触发、日志终止、Kettle 上传与一键建任务、权限控制
- P1：列表筛选、删除、下载、修改密码、多语言、分页、空态
- P2：提示文案一致性、时间格式、极限长度、刷新按钮、浏览器兼容

## 7. API / 业务流重点验证

### 7.1 登录与会话

- 验证 `/login` 成功后是否正确写入登录 Cookie。
- 验证错误账号/密码返回失败。
- 验证退出登录后 Cookie 清除。
- 验证会话失效后受保护接口行为。

### 7.2 任务管理主流程

- `/jobinfo/add`
  - 必填项：`jobGroup`、`jobDesc`、`author`
  - `scheduleType=CRON` 时必须校验合法 Cron
  - `glueType=BEAN` 时必须要求 `executorHandler`
- `/jobinfo/update`
  - 回归点：更新请求不应携带 `addTime`、`updateTime`、`glueUpdatetime`
  - 运行中任务修改 Cron 时，应重新计算下次触发时间
  - 子任务不能自引用、不能引用不存在任务、不能引用无权限任务
- `/jobinfo/start`
  - 启动后 `triggerStatus=1`
  - 下次触发时间重新计算
- `/jobinfo/stop`
  - 停止后 `triggerStatus=0`
  - `triggerLastTime/triggerNextTime` 置零
- `/jobinfo/trigger`
  - 手动触发应校验登录人与任务所属组权限
  - 触发后生成新日志

### 7.3 调度日志流程

- `/joblog/pageList`
  - 列表过滤与分页参数正确
  - 前端第一列显示日志 ID，第二列显示任务 ID
- `/joblog/logDetailCat`
  - 日志内容中 `<br>`、HTML 转义字符应被正常还原
- `/joblog/logKill`
  - 回归点：前端传参必须是日志 ID，不是任务 ID
  - 仅运行中日志允许终止

### 7.4 执行器管理与注册回调

- `/jobgroup/pageList/save/update/remove`
  - 手动/自动注册执行器展示一致
  - 内置执行器组 `xxl-job-executor-kettle` 在前端不可删除
- `AdminBizImpl.registry / registryRemove`
  - 执行器注册后应在仪表盘、执行器管理列表中反映在线状态
- `AdminBizImpl.callback`
  - 执行完成回调后，日志状态从运行中转为成功或失败

### 7.5 用户与权限

- `/user/pageList/add/update/remove/updatePwd`
  - 管理员可管理用户
  - 普通用户不可访问用户管理页面
  - 修改密码需校验旧密码正确
- 业务权限
  - 普通用户仅可操作 `permission` 中包含的执行器组任务
  - 涉及手动触发、子任务引用、一键建任务时均需复测权限

### 7.6 Kettle 分组与文件

- `/api/kettle/group/list/add/update/delete`
  - 分组名必填、不可重复、不可含 `/`、`\`、`..`
  - 有文件的分组不可删除
- `/api/kettle/file/list/detail/upload/delete/download`
  - `groupId` 非法时应失败
  - 上传文件仅允许 `.ktr/.kjb`
  - 同名文件重复上传应走版本升级
  - 下载时磁盘文件不存在应返回失败

### 7.7 一键创建 Kettle 任务

- `/jobinfo/createKettleJob`
  - `kettleFileId/fileId` 必填
  - 同一文件已关联任务时不可重复创建
  - 未指定 `jobGroup` 时应自动选择默认执行器组
  - 默认任务应为 `GLUE_SHELL`
  - 默认 Cron 为 `0 */5 * * * ?`
  - 脚本内容应包含 Kettle 安装路径、文件相对路径、日志路径
  - 创建成功后需把 `jobId` 回写到 Kettle 文件记录

## 8. 高风险回归清单

以下为每次发布前建议必跑的回归最小集：

1. 登录成功、失败、退出登录
2. 普通用户不可见“用户管理”，直访被拦截
3. 新增普通任务成功
4. 编辑任务成功，且更新请求不携带 `addTime/updateTime/glueUpdatetime`
5. 运行中任务修改 Cron 后仍可正常保存并重新计算下次触发时间
6. 启动任务、停止任务、手动触发任务均成功
7. 日志列表前两列顺序分别为 `Log ID`、`Job ID`
8. 运行中日志“终止”按钮可用，且传参为日志 ID
9. 内置执行器组 `xxl-job-executor-kettle` 不可删除
10. Kettle 文件上传仅接受 `.ktr/.kjb`
11. 同名 Kettle 文件重复上传后版本递增
12. 有文件的 Kettle 分组不可删除
13. Kettle 文件一键创建任务成功，默认创建为 Kettle 执行器 / `GLUE_SHELL`
14. 已关联任务的 Kettle 文件不可重复一键建任务
15. 仪表盘在线执行器、最近日志、失败数展示无明显错位或错数

## 9. 建议的执行顺序

建议手工测试按以下顺序执行，可减少环境切换成本：

1. 登录与权限验证
2. 执行器管理、用户管理基础数据检查
3. Kettle 分组与文件上传
4. 一键创建 Kettle 任务
5. 任务管理新增、编辑、启动、停止、触发
6. 调度日志列表、终止、详情
7. 仪表盘数据核对
8. 多语言、空态、失败态、会话过期与刷新场景
