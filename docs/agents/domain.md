# Domain docs

此文件说明工程技能在理解本仓库业务和架构时，应如何读取领域文档。

## 布局

本仓库采用 **single-context** 布局。

主要领域文档位置：

- 根目录 `CONTEXT.md`，如果存在。
- `docs/adr/`，如果存在，用于记录架构决策。

本仓库虽然包含 `server/` 和 `web/`，但它们属于同一个产品上下文：`xxl-job-kettle`。

## 开始探索前应读取

如果存在，应优先读取：

- 根目录 **`CONTEXT.md`**
- 与当前任务相关的 **`docs/adr/`** 里的 ADR

如果这些文件不存在，**静默继续**。不要因为缺失这些文件而阻塞任务，也不要主动要求先创建它们。

`/grill-with-docs` 等文档生产型 skill 会在确实需要沉淀术语或架构决策时，再逐步创建这些文件。

## 文件结构

single-context 仓库结构约定：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-example-decision.md
├── server/
└── web/
```

## 使用项目术语

当输出 issue 标题、重构建议、问题假设、测试名时，应优先使用 `CONTEXT.md` 中定义过的项目术语。

不要随意改用近义词，尤其不要使用 `CONTEXT.md` 明确避免的说法。

如果需要使用的概念还没有出现在 `CONTEXT.md` 中，说明可能存在两种情况：

1. 当前表述不是项目已有语言，需要重新考虑；
2. 项目确实缺少术语沉淀，可后续通过 `/grill-with-docs` 补充。

## 标出 ADR 冲突

如果输出内容与已有 ADR 冲突，应明确指出，而不是悄悄覆盖：

> _与 ADR-0007 冲突，但值得重新讨论，因为……_
